# Final report: direct uniform-grid discrete Hankel transform

Date: 2026-08-28

## Executive result

The fastest demonstrated implementation is the product-safe, ratio-4 blocked
large-argument Bessel expansion with ordinary FFTW transforms:

```text
terms = 10, cutoff z0 = 30, block ratio = 4, FFTW threads = 10
```

At `N=65536`, the primary deterministic complex-random workload has a
101-sample median of **13.590 ms**. Setup is **0.695113 s** and the accounted
reusable plan storage is **74,849,448 bytes** (about 71.4 MiB, excluding FFTW
internal allocations and caller buffers).

This is the fastest result that survived the completed accuracy screens. It is
important not to overstate the evidence: full arbitrary-vector MPFR norms at
`N=65536` were not completed because a dense high-precision reference is
impractical. The result is therefore an empirical/provisional winner, not a
universal certificate for every binary64 input at the primary size. Full-vector
MPFR tests, adversarial residual-sign vectors, independent selected-row
large-N checks, and full endpoint-column controls all passed in their stated
scopes.

## 1. Winning algorithm

Let

```text
alpha = 2*pi/N,  z = alpha*m*n,  theta = z - pi/4.
```

For positive `z`, use the order-0 Hankel expansion

```text
J0(z) ~= sqrt(2/(pi*z)) * sum(q=0..K-1) b[q] z^(-q) T[q](theta),
```

where `T[q]` is cosine for even `q`, sine for odd `q`, and the signed
coefficients are generated by the standard order-0 recurrence. The first
terms are

```text
sqrt(2/(pi*z)) * (cos(theta) + sin(theta)/(8*z)
                  - 9*cos(theta)/(128*z^2)
                  - 225*sin(theta)/(3072*z^3) + ...).
```

With `p=q+1/2`, each term factors exactly on this integer grid:

```text
z^(-p) = alpha^(-p) * m^(-p) * n^(-p).
```

Thus, for one output band and one order, define

```text
F_q[m] = sum_{n=n0}^{N-1} x[n] * n^(-p) * exp(+i*alpha*m*n).
```

`F_q` is an ordinary length-`N` DFT. The negative phase is obtained without a
second transform from `F_q[(N-m) mod N]`, since the phase is an exact integer
DFT phase even when `x` is complex. A constant amount of arithmetic combines
the two bins into the shifted cosine or sine projection and applies the output
scale.

The crucial stability device is the product-safe mask. For an output band
`m in [b,4b)`, choose

```text
n0 = ceil(z0*N/(2*pi*b)).
```

Only `n >= n0` enters the asymptotic FFT. Every omitted pair is evaluated by
the exact binary64 `j0` table and added as a direct correction. The axes are
exact: `y[0] = sum(x[n])` and every positive row includes `x[0]`. This prevents
the catastrophic cancellation that occurs if a global asymptotic expansion is
evaluated near `(m,n)=(1,1)` and then corrected by subtraction.

For fixed cutoff and ratio, the asymptotic work is

```text
O(K * N * log(N)^2)
```

with the simple full-length-FFT implementation, and the direct table is
`O(z0*N*log_4(N))`. Working storage is `O(K*N + z0*N*log_4(N))`; no dense
`N x N` matrix is stored. At the target size the profile has six active bands,
60 full FFTs per apply, and 6,603,633 exact direct entries.

This is a specialization/hybrid of the asymptotic product-grid ideas in
Townsend's fast DHT work, with the exact integer-grid phase collapse and the
product-safe masking/direct-row schedule developed here. It is not claimed as
a new general asymptotic-DHT theorem, and it is not the Bessel-zero or
logarithmic-grid operator.

## 2. C implementation

The canonical implementation is [src/dht_asym.c](../src/dht_asym.c), with the
public header [src/dht.h](../src/dht.h). The selected forwarding pair is in
[best/](../best/). The implementation uses binary64 throughout and does not
use `-ffast-math` or `-Ofast`.

Dependencies on the measured machine are Apple libdispatch, threaded FFTW
3.3.10, and libm. MPFR/GMP are required only by the accuracy harness. The
exact build is:

```sh
make -B all
```

The one-case commands are:

```sh
make verify
make benchmark
make direct
```

The full timing sweep is:

```sh
./bench/run_winner.sh
```

The supported C API is:

```c
dht_plan *dht_plan_create(size_t n, double tol, unsigned threads);
int dht_apply(const dht_plan *, const dht_complex *x, dht_complex *y);
void dht_plan_destroy(dht_plan *);
```

`x` and `y` must not overlap. A plan may be reused sequentially; concurrent
calls on one plan are unsupported because the FFT scratch is shared. The
profile constructors and metadata accessors are also exposed for benchmarking,
but only the release profile selected by `tol=1e-13` has the accuracy evidence
reported here. FFTW thread initialization is checked and intentionally kept
alive for the process lifetime.

## 3. Accuracy

The acceptance metrics are normalized complex L2 error <= `1e-13` and scaled
complex Linf error <= `1e-12`, against an independent multiprecision reference.

| Test scope | Result for `(10,30,4)` |
|---|---:|
| 25 full-vector cases, 256-bit MPFR, `N=32..512`, five input families | all PASS; worst L2 `2.9654e-15`, worst scaled Linf `9.1671e-15` |
| Independent 256-bit MPFR residual-sign full vectors, `N=32..512` | all PASS; worst L2 `9.8090524e-15`, scaled Linf `1.4735251e-14` |
| `N=65536` random selected-row diagnostic, nine rows | max row-relative `8.3716e-15` (diagnostic threshold `1e-11`) |
| Full `N=65536` delta column at `n=1` | L2 `1.6267e-16`, scaled Linf `2.7990e-16` |
| Full `N=65536` delta column at `n=N-1` | L2 `1.1421e-15`, scaled Linf `7.9047e-16` |
| Independent 400-bit selected large-N residual-sign screening | approximately worst L2 `1.05e-14`, scaled Linf `1.09e-14` |

The residual-sign construction is valuable because it aligns the input with
the scalar asymptotic remainder. It rejected the faster-looking `(12,18,4)`
profile: an independent 400-bit full-vector run at `N=64` measured
`3.19267630336555019e-13` L2 and `5.47311324551836609e-13` scaled Linf.

Tolerance experiments at `1e-12`, `3e-13`, and `1e-13` all select `(10,30,4)`
and pass the available checks. `3e-14` selects the slower, larger-margin
`(10,40,4)` profile; it also passes the available checks. These are empirical
profile-selection results, not a formal guarantee for arbitrary user-supplied
tolerances.

The missing item is a complete arbitrary-vector, full-output MPFR norm at
`N=65536`; the current harness explicitly labels its non-delta large-N checks
as selected-row diagnostics. This limitation is recorded rather than being
silently promoted to a certification claim.

## 6. Research findings

### Literature and related methods

The closest published foundation is Townsend's analysis-based fast DHT,
which uses large-argument Bessel expansions, geometric decomposition, and FFT
structure. Beckman--O'Neil's nonuniform fast Hankel transform provides a
general local/asymptotic plus NUFFT framework. On this exact integer grid,
generic nonuniform phase machinery collapses to ordinary FFTs and a partner
bin, which is the key specialization here. The complete source list is in
[research/sources.md](sources.md).

FFTLog and QDHT were accounted for but do not natively evaluate this matrix:
they use logarithmic and Bessel-zero grids, respectively, so the required
input/output conversions would be input-dependent and would change or
approximate the finite operator. The 2026 convolutional-Gaussian FFT method
has the same continuous/quadrature-grid mismatch for this target.

### Failed or noncompetitive families

- A global asymptotic FFT plus direct residual correction fails in binary64:
  asymptotic terms near `(1,1)` become enormous and cancellation destroys the
  correction.
- Lower-order masked profiles fail residual-sign tests even when smooth and
  ordinary random tests pass. In particular `(12,18,4)` fails decisively.
- Butterfly/complementary-low-rank blocks have useful structure, but generic
  blocks need rank about 24 at `1e-13` and 26--28 with accumulation margin;
  the resulting hierarchy was slower and substantially larger.
- Radial projection/Cartesian FFT embeddings require large angular or Cartesian
  grids and interpolation; measured work models were far above the blocked
  FFT approach.
- FMM/HSS/HODLR-style compression did not maintain sufficiently small rank in
  the transition/interior blocks.
- FFTLog, QDHT, CGFHT, and generic Beckman--O'Neil NUFHT remain useful
  continuous or nonuniform baselines, but their conversions/NUFFT spreading
  are not competitive for the exact arithmetic-grid kernel.
- Pruned FFT, vDSP, `-Ofast`, and alternate layouts were measured. Ordinary
  FFTW with contiguous order-major batches and the band-aware direct schedule
  gave the best safe result; unsafe compiler math was not retained.

### Main mathematical insight

The exact `2*pi*m*n/N` phase is more valuable than a generic Hankel identity:
after separating powers of `m` and `n`, every far-field asymptotic order is an
ordinary DFT, and complex input does not double the FFT count because the
negative phase is the periodic partner bin. The decisive numerical insight is
that the approximation must be masked by the product `m*n`, not merely by one
coordinate; direct near-field evaluation is cheap enough at fixed cutoff to
make that stability constraint practical.


CSV. The residual-sign reproduction is:

```sh

  research/adversarial_k12.c build/dht_asym.o \

  -o /private/tmp/dht_adversarial_final

```

are retained in the worker reports under `research/`.
