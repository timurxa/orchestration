# Literature and implementation sources

The target in this archive is the exact arithmetic-grid matrix
`A[m,n] = J0(2*pi*m*n/N)`. A method is not promoted merely because it is a
fast Hankel transform for a different grid or a continuous integral.

| Source | Relevance to this target | Complexity / accuracy implication | Implementation or primary link |
|---|---|---|---|
| Townsend, *A Fast Analysis-Based Discrete Hankel Transform Using Asymptotic Expansions* (2015) | Closest published analysis: large-argument Bessel expansion, geometric blocks, FFTs, and Neumann addition. This project adapts the asymptotic/product-grid idea; its zero-shift representation does not require a Neumann correction. | Published `O(N (log N)^2 / log log N)` for fixed accuracy; its remainder analysis motivated the product-safe masks here, while the implementation below has its own full-FFT cost. | [SIAM paper](https://doi.org/10.1137/151003106), [arXiv](https://arxiv.org/abs/1501.01652), [MATLAB code](https://github.com/ajt60gaibb/FastAsyTransforms) |
| Beckman & O'Neil, *A Nonuniform Fast Hankel Transform* (2026 journal article; 2024 preprint) | General nonuniform baseline using local and asymptotic expansions plus NUFFTs. Exact uniform integer phases are a special case where full phase transforms can be ordinary FFTs; that specialization is project algebra, not their implementation. | Near-linear fixed-tolerance work; generic Type-3 NUFFT machinery is unnecessary for the full direct grid, but local/asymptotic error budgeting is relevant. | [arXiv preprint](https://arxiv.org/abs/2411.09583), [SIAM DOI](https://doi.org/10.1137/25M1796758), [Julia code](https://github.com/pbeckman/FastHankelTransform.jl) |
| NIST DLMF §10.17 | Primary asymptotic formula and real-argument remainder facts for `J0`. | Supplies the first-omitted-term bound used to choose order/cutoff; binary64 cancellation still requires a product-safe partition. | [DLMF 10.17](https://dlmf.nist.gov/10.17), [remainder subsection](https://dlmf.nist.gov/10.17.iii) |
| NIST DLMF §10.23 | Neumann/addition-theorem reference used to account for Townsend's correction and the exact-grid collapse. | At zero perturbation only the zeroth addition term remains. | [DLMF 10.23](https://dlmf.nist.gov/10.23) |
| Hamilton, FFTLog (2000; Talman 1978 predecessor) | Important fast Hankel baseline, but it computes a periodic sequence on a logarithmic mesh rather than this direct arithmetic grid. | `O(N log N)` on the log grid; uniform-to-log resampling and back would be input-dependent and timed, and does not preserve the exact matrix at `1e-13`. | [FFTLog site](https://jila.colorado.edu/~ajsh/FFTLog/index.html), [Hamilton preprint](https://arxiv.org/abs/astro-ph/9905191), [Talman DOI](https://doi.org/10.1016/0021-9991(78)90107-9) |
| Yu et al., *Quasi-discrete Hankel transform* (1998) | QDHT uses Bessel-zero quadrature nodes and a different matrix. Included as a grid-conversion baseline, not as a silent substitution. | Efficient on its prescribed zero grid; conversion to the exact integer grid is input-dependent and fails the direct-operator identity unless paid for and validated. | [Optics Letters DOI](https://doi.org/10.1364/OL.23.000409), [PubMed record](https://pubmed.ncbi.nlm.nih.gov/18084527/) |
| Malinka, *Improved algorithm for the quasi-discrete Hankel transform* (2021) | Recent QDHT refinement; same Bessel-zero-grid limitation for this task. | Improves tail/weight accuracy without changing the grid mismatch. | [JOSA A DOI](https://doi.org/10.1364/JOSAA.403065) |
| Tian & Li, *An efficient discrete Hankel transform based on convolutional Gaussian FFT* (2026) | Required recent 2026 convolutional-Gaussian method. It targets continuous EM Hankel integrals and shifted/convolutional sampling, not the exact `mn/N` matrix. | Toeplitz/circulant convolutions can be fast, but uniform-grid conversion, quadrature, and interpolation are input-dependent and must be included here; no exact-grid promotion. | [Earth, Planets and Space article](https://link.springer.com/article/10.1186/s40623-026-02436-5) |
| Li et al., *Butterfly Factorization* (2015) | Candidate for the oscillatory structured matrix through complementary low rank. | Generic interior blocks measured here need rank about 24 at `1e-13` and 26--28 for margin; estimated storage/work loses to the masked FFT candidate. | [arXiv](https://arxiv.org/abs/1502.01379), [published DOI](https://doi.org/10.1137/15M1007173) |
| Li & Ying, *Multidimensional Butterfly Factorization* (2015) | Covers Fourier-integral kernels with singular/transition regions; relevant to possible radial/Cartesian embeddings. | Requires transition handling and a large coefficient hierarchy; no competitive exact-grid implementation was demonstrated. | [arXiv](https://arxiv.org/abs/1509.07925) |
| FINUFFT documentation | Reference implementation for the NUFFT component of generic NUFHT and radial/projection alternatives. | Type-3 and interpolation costs remain input-dependent; exact integer full-grid phases are cheaper with ordinary FFTW. | [FINUFFT documentation](https://finufft.readthedocs.io/en/stable/) |
| Kapur & Rokhlin, *An algorithm for the fast Hankel transform*; classical FMM background | Directly relevant fast-Hankel/FMM precedent, while classical FMM supplies the general separated-interaction framework. | The project’s local rank tests did not establish a competitive H/H2/FMM factorization for this matrix; this is a local result, not an impossibility theorem. | [Kapur--Rokhlin Yale report](https://engineering.yale.edu/application/files/5917/3706/2172/tr1045.pdf), [Greengard--Rokhlin DOI](https://doi.org/10.1016/0021-9991(87)90140-9) |
| Thompson, *The complete expansion for Twersky's formula* (2026) | Current Schlömilch-series literature checked for a hidden product/convolution identity. | Relevant analytic identities do not turn the arbitrary finite `J0(2*pi*m*n/N)` matrix into a Toeplitz convolution at the required accuracy. | [IMA Journal 2026](https://doi.org/10.1093/imamat/hxag003) |

## Local platform/library evidence

The benchmark machine is a MacBookPro18,3 with Apple M1 Pro (10 cores: 8
performance and 2 efficiency), 32 GB RAM, macOS 26.5.2 / Darwin 25.5.0,
arm64. The compiler is Apple clang 21.0.0. Accelerate is installed; the
reproducible production build currently uses Homebrew FFTW 3.3.10 and MPFR/GMP
from `/opt/homebrew`. vDSP and compiler-option experiments are archived in
worker reports; the final gate is always rerun with the selected build.
