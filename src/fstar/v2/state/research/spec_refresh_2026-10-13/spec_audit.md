# F* v2 implementation spec audit

Scope: read-only comparison of `src/fstar/v2/implementation_spec.md` with `src/fstar/v2/key_correctness_theorems.md`. Line numbers below refer to current spec unless stated. Main finding: spec captures many desired claims in prose, but the boundary between abstract obligations, executable graph language, and concrete refinement remains underspecified or internally inconsistent. The theorem note should drive edits to §2.2.1, §4.1–4.3, §6 and theorem dependency map.

## Cross-cutting findings

1. **All-environment graph typing: intent present, rule not executable.** §2.2.1 says “may be” an environment-indexed family and asks for pointwise equality at lines 476–512. But actual current builder has one fixed input carrier `A` per node and output `B input`; see theorem note lines 94–98. Spec switches from that actual shape to a hypothetical environment-indexed `Wiring` at lines 508–510, without defining `LegalEnvironments`, equality derivability, or rejecting an unprovable direct edge. This is the sharpest contradiction. Define the actual quantified context: for each node `k`, fixed `A_k`, `B_k:A_k -> Type`, and input evaluator `eval_k(ρ):A_k`; output port is `B_k(eval_k(ρ))`. Then state full `WireTyping` judgment for every legal environment, including direct output and recursive pair/projections. If future API allows environment-varying input carrier, specify that as a separate extension, not current semantics.

2. **Direct edge needs strict, signature-derived compatibility criterion.** Lines 476–489 permit typed compatibility tables/proof certificates, including potentially edge-context evidence; theorem note 51–66 says no node-supplied/context-dependent edge proof, no runtime result, adapter, or execution. State acceptance as: for every legal `ρ`, if consumer wire is direct `OutputWire p`, derive `B_p(eval_p(restrict ρ)) = A_c` from exact resolved signatures and static graph constraints only; otherwise reject descriptor. For Pair/Fst/Snd, recursively check full consumer wire; do not require whole producer type equal whole consumer type. No witness payload whose trust depends on per-run output. The note's vector `n`/vector `3` case (68–91) should be adopted into spec as normative counterexample.

3. **Graph typing and semantic provenance are correctly distinct in note but not fully theoremized in spec.** Spec has append-time assertions at lines 891–899 and contracts P6/P7/P13, but no single theorem establishes typed graph + authorized result + recovery at every prefix. Add `recovered_semantic_graph_correctness` as in theorem note lines 173–228; identify assumptions: valid authorized `RunStarted`; exact registry/manifest and codecs (P0); legal trace / append-prefix store refinement; adapter resume/validation contract; plus abstract executor service contracts. Keep artifacts out unless P9 included.

4. **Every-cut theorem proves storage prefix/replay, not semantic authorization by itself.** §4.3 lines 959–1005 already says that correctly. The theorem note strengthens to a semantic prefix property. Add explicit `RecoveryPreserves` corollary over authorized trace `T`: each cut loads prefix `Jc` of `T`, `recover = replay(Jc)`, and `WF_semantic(Jc)` (each completion/outcome/graph commit has provenance). Need append authorization preserved by no external mutation and store protocol integrity. Don't claim replay can re-prove local function or generator provenance without rerunning; replay checks durable bytes/type/identity, while trace provenance comes from P13/store premise.

5. **Committed no-rerun needs “cannot authorize/dispatch” distinction.** Spec lines 939–946 and P6 line 1171 state absorbing/reuse/no reauthorization; theorem note lines 232–263 clarifies crash may discard uncommitted computation, so physical execution can repeat before commit. Specify no live duplicate claim per occurrence, no launch/dispatch after committed completion/graph commitment, while allowing recomputation after crash before commit. For adapter, pending durable intent resumes same logical call; don't equate no second physical transport attempt with exactly-once external effect.

6. **Abstract executor theorem and concrete refinement are conflated in P13.** Theorem note lines 232–263 explicitly asks for abstract all-interleavings proof, then separate concrete worker pool/journaler/adapter refinement. Spec §4.1 has a `StoreModel`, §4.2 prose execution, and P13 concrete “extracted runner” but no numbered P target for abstract executor safety. Add `ExecutorInterleavingPreserves` target after P10/P13 dependencies; define volatile task state, unique in-flight claims, arbitrary completion ordering, serialized legal appends, only committed dependencies visible, recovery from prefix. Then keep P13 as implementation refinement of that abstract executor plus store/adapter services. P14 termination separate.

7. **Abstract theorem vs host refinement premises must be named by owner.** P0/P2/P3/P4/P6/P7/P10/P13 are abstract/kernel properties; actual store bytes, process crashes, extraction, scheduler, adapter are host obligations. Lines 1189–1212 enumerate some assumptions, but P10's theorem formula talks directly about `load(H,c)` and concrete cuts. Label P10 as conditional abstract store-refinement theorem; separately require implementation proof that SQLite/host append/load satisfies it. Same for P13: does not discharge extraction/build identity correspondence (lines 1194–1200).

## Formal additions recommended

1. **`TypedEdges(G)`** (theorem note 182–198): quantify every node `k` and every legal typed port environment `ρ`; resolve `Work A_k B_k`; require whole wire eval has type `A_k`. For direct output `OutputWire p`, output type is `B_p(x_p(restrict_prefix ρ))`; equality to `A_k` must be derivable from signatures/static graph constraints, else `resolve_graph=None`. Pair/projections follow recursive rules. No runtime values, adapter, validator, or node proof payload participates.
2. **`ReadyInput(S,k,x)`** (note 185–198): ready iff all and only referenced dependencies have committed outputs; reconstruct sparse input from root plus those outputs; prove equals typed full-environment evaluator for every full env compatible on those refs. Required because current source evaluator consumes full `PortEnv`, but independent ready nodes may execute before unrelated ports finish.
3. **Three provenance predicates**: local completion equals pinned `CodeRef.run(x)`; external outcome equals exact validator accepted result correlated with same durable intent/input; generator commitment equals pinned generator output at exact input/allocation and resolved child bytes/plan. Keep generator child output as later graph output of type `B_k x`, not a `NodeCompleted` value.
4. **`RecoveryPreserves`**: for authorized trace `T`, every cut yields prefix `Jc`, `recover=replay(Jc)`, and semantic WF; local committed output is reused, generator committed bytes are reused, external intent resumes same key. This is composition of append authorization + store refinement + replay, not a replay-only theorem.
5. **`ExecutorInterleavingPreserves`**: arbitrary local/generator finish order and distinct external response order; unique in-flight occurrence ownership; commits serialized; uncommitted results volatile/recomputable; no committed occurrence rerun/redispatch; only committed outputs enable dependents. Keep concrete implementation refinement separately.

## Open questions to resolve in spec refresh

- Does current graph type model have fixed input carrier per Work (matching `Graph.fst`) or input carrier varying over port environment (lines 477–510)? State one model. Theorem note says current API is fixed carrier.
- Is a “typed compatibility certificate” a proof derivation from static signatures, or a caller/event payload? Only former meets strict edge criterion. Prefer syntax-directed resolver derivation with no serialized per-edge proof field.
- Do all-environment constraints include root input refinements and exact graph constants, but exclude outputs not yet committed? Define `LegalEnvironments(G)` as type-theoretic environments, not currently observed runtime state.
- Does P3 `WF` include event provenance? If yes, it depends on P13 and store integrity. If no, introduce semantic WF / authorized trace invariant.
- Should P5 remain a standalone theorem or be named as P4+P10 recovery corollary?
- Who proves exact extracted code/manifest correspondence, SQLite durability, worker uniqueness and adapter resume semantics? Mark each as owned concrete refinement/premise, not silently as F* theorem.
