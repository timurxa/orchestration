# V2 universal edge design review

Read-only review of the strict edge contract against current F* v2 interfaces and four implementation routes. Recommendation: keep universal, static semantic rule; implement acceptance through pinned typed resolvers (optionally backed by a small schema/reflection language); do not require per-node proof bytes. Narrow P1/P2 completeness to graphs accepted by this resolver unless project intentionally funds general F* proof reification.

## Existing boundary

- Durable graph syntax has only work/codec identities, node keys, wire constructors, constant bytes; no closure or typed witness ([Kernel.fst:63–87](/Users/alex/areas/productive/orchestration/src/fstar/v2/src/WorkflowV2.Kernel.fst#L63)). Graph codec round-trips this syntax ([Kernel.fst:126–135]).
- `Work` permits arbitrary dependent `output: input -> Type0`; local work is indexed `run`, external validation returns `option (output x)` ([Kernel.fst:99–124, 177–186]). Exact registry lookup identifies package but does not manufacture type equality (see resolver feasibility note [lines 7–34](/Users/alex/areas/productive/orchestration/src/fstar/v2/state/research/V2-03-resolver-feasibility-2026-10-13.md#L7)).
- In-memory graph model already has env-indexed port families and typed wire witnesses for root/constants/output/pairs/projections ([Graph.fst:150–190, 304–381]). But `TypedNodesSnoc` demands node input wire type `fun _ -> a`: each Work has fixed input carrier, while its output may vary with reconstructed input ([Graph.fst:606–623]).
- Thus the desired direct edge rule is universal but node boundary target is fixed: for consumer `c: Work A_c B_c`, producer `p` wire value has type `B_p(x_p(ρ))`; accept direct `OutputWire p` only if `forall ρ ∈ LegalEnvironments(G), B_p(x_p(restrict_prefix ρ,p)) = A_c` follows from pinned signatures and static graph constraints. Reject when not derivable. For arbitrary whole input wires, recursively type Pair/Fst/Snd; producer output need not equal consumer input as a whole. Do not use observed outputs or validator behavior to establish edge typing.
- Current `graph_wf` asserts existential typed witness, not existence of an executable reconstruction algorithm ([Graph.fst:763–798]); source witness is not in bytes. This is exactly the P2 gap.

## Four routes

| Route | Universal all-environment equality? | Decode/recovery without runtime or supplied edge proof? | Boundary |
|---|---|---|---|
| Typed constructor AST with author-time witnesses | Yes, while authoring: F* type checks the typed constructor and witness. | **No, not generically.** Graph codec erases witnesses. Raw syntax plus Work identity cannot reconstruct an arbitrary equality proof. Works after decode only if syntax is in a restricted language with a resolver that rebuilds proof, or if graph bytes retain proof evidence (forbidden by requested constraint). | Good builder front-end and trusted construction API; not a standalone P2 solution. Builder completeness cannot imply resolver completeness. |
| First-order schema/type language plus sound and complete checker | **Yes within schema language.** Checker must reason symbolically over graph inputs / all legal port environments and prove denotation equality, not test sample values. | **Yes**, if schemas and equality decision procedure are fixed by exact pinned manifest and derivable from decoded graph syntax/prefix. No typed witness bytes needed. | Soundness/completeness are relative to the schema grammar and supported family lemmas. Cannot cover opaque arbitrary F* `Type0` families unless represented in language. Existing schema-token equality alone is insufficient; see spec §2.2.1 476–512 and resolver feasibility note 38–54. |
| Proof-certificate / reflection checker | Explicit serialized equality certificate: **yes if checker sound**, but certificate is node/graph-supplied edge proof bytes, so **fails stated no-supplied-edge-proof constraint**. | Reflection checker that derives proof from canonical type/schema syntax, without proof bytes: **yes within its reflected fragment**; functionally this is a schema-language checker. | General F* proof term certificate can broaden accepted equalities, but requires canonical proof language + checker and violates no proof-byte rule. Without certificate or type reification, reflection cannot conjure arbitrary erased proof. Prior certificate analysis admits bytes must be encoded and completeness limited to calculus/lemmas ([local-wire-equality-certificates.md:89–147](/Users/alex/areas/productive/orchestration/src/fstar/v2/state/research/V2-03-local-wire-equality-certificates-2026-10-13.md#L89)). |

Arbitrary opaque equality still impossible unless callback embeds a constructive proof/procedure or derives it from represented static constraints. |

### Assessment details

**1. Typed constructor AST.** In-memory builder can be maximally expressive: `wiring_typed` carries exact equality implicitly through F* typing. `add_node` accepts a `wiring ... (fun _ -> a)` and extends port telescope with `b (eval_wiring w prior)` ([Graph.fst:523–543]). This establishes author-time typing, but descriptor serializes `wiring_syntax`, not `wiring_typed` ([Graph.fst:619–623]; [Kernel.fst:76–87]). Therefore it proves P1 soundness for graphs actually built, not generic P2 reconstruction after process restart. Could serialize/rebuild AST only if it denotes a restricted type/equality language; otherwise AST identifies types but not erased proof connecting them. Re-running a builder callback is just resolver route, and re-running a generator would violate committed graph recovery contract.

**2. Schema language.** Best route for stable byte-only graph syntax if API accepts controlled type vocabulary. Give every exact Work input/output family and codec a schema expression, with proof that schema denotation equals actual F* carrier/family. Symbolically substitute root, constants, and prior output expressions; type-check structural Pair/Fst/Snd; prove direct edge equality for all legal environments. A decision procedure can return Boolean; F* theorem proves acceptance sound, and completeness is for supported schema equalities. Need represent graph-specific constraints (e.g. producer input is statically fixed to `0`, so `Prime 0 = Prime 0`) or resolver rejects. PairWire remains structural and needs no separate pair codec ([pairwise simplification note:20–40](/Users/alex/areas/productive/orchestration/src/fstar/v2/state/research/V2-03-pairwire-simplification.md#L20)). No finite compatibility table keyed only by producer/consumer Work suffices for graph-local constants/ranges; example `input nat -> Prime input` wired to `0` feeding `Prime 0` is accepted pointwise though a global `forall n` table rejects (certificate note 7–19).

**3. Certificate/reflection.** Separate two meanings. A graph-supplied certificate gives a compact proof of a proposition universally quantified over legal environments; checker proof validates it before execution. It satisfies semantics and recovery only by making certificate canonical durable bytes/sidecar, but directly violates constraint “without ... node-supplied edge proofs or typed witness bytes.” A reflection decision procedure can take first-order type/family syntax, normalize or prove equality without accepting proof payload; this meets constraint but only for reflected fragment. “General F* reflection” does not solve erased arbitrary type equality unless enough F* syntax and a sound checker for that fragment are represented. Existing source type representations are opaque `Type0`; arbitrary type equality is not generally decidable from identities/syntax ([resolver feasibility note:13–34, 102–109](/Users/alex/areas/productive/orchestration/src/fstar/v2/state/research/V2-03-resolver-feasibility-2026-10-13.md#L13)).

**4. Pinned callback.** Strongest practical path under no-proof-bytes rule. Resolver is code tied to exact pinned Work package; receives exact reconstructed typed prior prefix and raw node input wire; returns `None` or universally typed `wiring` whose `wiring_syntax` equals descriptor wire. It cannot run Work to discover a value. Since callback is rerun at graph decode/recovery using same manifest identity, it recreates the proof on each recovery. Callback may use F* lemmas known statically and/or schema checker; callback does not get a per-node proof payload. Graph bytes need not change. But `graph_wf` must be redefined as finite/unique/topological + all node resolver calls succeed + graph output wire resolves at exact boundary type. `resolve_graph_complete` is then only for that predicate. Avoid falsely claiming raw existential `graph_wf` completeness: not every raw typed witness is algorithmically recoverable. This matches current alternative note recommendation (resolver feasibility note 111–160).

## Impossibility boundary

There is no general algorithm that, from arbitrary erased F* `Type0` values, first-order identity strings, and raw wire syntax, decides arbitrary type equality or reconstructs an arbitrary erased proof of it. Exact `Work` lookup says which opaque package was selected; it does not expose a canonical syntax for its `Type0`, nor a proof of `B_p(x_p(ρ)) = A_c`. The required proposition is universal over every legal environment, so executing a producer, validating an external reply, or testing one recovered output cannot establish it. A constructive implementation must choose at least one:

1. restrict types/equalities to decidable schema language and prove schema denotations;
2. pin a resolver that can prove accepted graph-local equalities, narrowing validity to resolver-supported graphs;
3. persist proof evidence and trust only a sound checker (rejected by present no-proof-bytes constraint); or
4. reify/check a sufficiently broad F* proof language, a major subsystem, still requiring proofs represented rather than erased.

No choice preserves “all arbitrary typed F* DAGs” plus “raw syntax only” plus “generic decode resolver” simultaneously.

## Recommended specification language

Keep semantic contract universal and method-independent; define executable acceptance by pinned resolver support:

> **Universal edge typing.** For every decoded descriptor `g`, every node `c`, and every legal typed port environment `ρ` of `g`, resolve `c` to its exact pinned `Work A_c B_c`. Its complete input wire evaluates to an `A_c`. In particular, if that wire is `OutputWire p`, and `p` resolves to `Work A_p B_p`, then the equality `B_p(x_p(restrict_prefix ρ,p)) = A_c` holds for every such `ρ`. The equality is established only from exact pinned package definitions and static graph constraints, before execution. Pair, projection, root, and constant wires are derived recursively. No observed output, external reply/validator, runtime check, or caller-supplied edge proof establishes this property. A descriptor is rejected before execution if the pinned resolver cannot construct this universal typing witness.
>
> **Resolver acceptance/completeness boundary.** `resolve_graph(bundle,x,g)` processes the decoded graph in topological order. For each node it invokes the resolver bound to the exact pinned Work entry with the already-resolved typed prefix and that node's wire. `Some wiring` must have exactly the serialized wire syntax and type `fun _ -> A_c`; `None` rejects graph. Resolver outputs are transient proof objects, never serialized. Define `resolver_supported(bundle,x,g)` as successful resolution of all node inputs and output wire at exact graph boundary type. Define `graph_wf` to include this condition. P1/P2 soundness cover all accepted descriptors; completeness covers exactly `resolver_supported`/builder-expressible DAGs, unless a stronger theorem proves every raw semantically typed DAG is resolver-supported. Root and generated graphs use same resolver after decode. Pin resolver code and any schema/equality engine in exact manifest across recovery.

This semantic contract remains strict and universal; callback internals may use schema/reflection, but their allowed inputs exclude runtime values except statically represented root/constant terms. For input-dependent output types, resolver proves equality as a family over all legal environments, not over one execution's `x`.

## DAG acceptance decision item

**Decision recommended: resolver-certified DAG, no edge-proof bytes.**

- `GraphDesc` bytes remain first-order topology/wire syntax.
- Exact pinned Work package resolves both operation and its input-wire resolver through one canonical manifest; resolver identity/code is part of the pinned package identity.
- Builder `add_node` accepts graph only via resolver and produces transient typed witness. Decoded root and committed child graph run same resolver.
- `graph_wf := finite ∧ unique ∧ topological ∧ exact identities/codecs/constants ∧ all resolver input judgments succeed ∧ output wire has exact declared boundary type`.
- `P1` completeness means every resolver-certified finite typed DAG (equivalently every graph accepted by API) is constructible, not every abstract DAG with some erased F* proof.
- `P2` completeness means every descriptor satisfying this resolver-based `graph_wf` resolves; decoder rejects unsupported equalities.
- Preserve user-facing “universal all legal environments” acceptance rule. Name restricted expressive boundary plainly: opaque F* equalities unsupported by pinned resolver are rejected even if an author could prove them interactively.

Strongest objection: callback route puts proof power in trusted pinned code and can make `graph_wf` vacuously narrow if each Work resolver accepts only trivial wires. Counter: P1's explicit resolver-relative completeness plus API builder reachability makes the boundary honest; manifest audit and future schema language can enlarge supported set without changing soundness. If project requires broad language portability across Work packages, prefer schema + decision procedure as resolver implementation, but do not claim arbitrary F* completeness.

## Remaining design questions

- Is resolver per Work package or graph-level registry wrapper? Current module dependency direction makes `Work`-embedded `Graph.wiring` awkward; identity must bind the resolver either way.
- Which graph constraints are represented statically (root refinement, constants, dependent input symbolic terms)? Define `LegalEnvironments` independently of current state.
- Does root/output wire resolver need a graph-boundary callback, or are graph boundary `output x` families always statically derivable from typed wire syntax?
- How strict should P1 completeness language change: “resolver-supported DAGs” or “graphs constructible by public builder”? Prefer declare equivalence theorem between them.
- Should schema and callback be mandated now or leave callback as implementation mechanism? Recommendation: mandate resolver contract and pinning; allow schema/reflection as internal implementation, then prototype a schema-supported fragment.
