# S2-05 — transition-model adversarial audit

**Scope:** normative `implementation_spec.md` §§4.1, 5, P3/P8; active DAG acceptance. Read S2-02/03/04 reports as upstream contract evidence. **No F* source, verifier, or tests.** Verdicts below assess specification targets only; P3/P8 are not discharged source results.

## Verdict

`replay(J)` is intended as sole logical workflow state, but is not yet a complete transition model. It is well-scoped against other mutable workflow state: checkpoints must equal replay; controller handles are volatile; provenance is ghost history; pinned registry and artifact backing are explicit immutable/service contracts. Precisely, replay depends on the journal **and** the stable manifest/bundle context named by its events, not bytes in isolation. Artifact objects and external effects remain service state; they are not encoded into `State` and require P9/P7. No contradiction if “sole durable state” means workflow-control state under those contracts.

P3 currently specifies event families, intended guards, several derived ledgers, and target invariants, but not constructor definitions or complete state updates. `type Event`, `type State`, `apply`, `replay`, `WF`, and legality are abstract. “`apply` accepts only a legal transition” plus “legal event” does not define legality. Thus deterministic fold is a shape, not yet a concrete deterministic transition machine. WF preservation can become circular if “legal” means “preserves WF.”

## Cross-cutting theorem gaps

1. **Define the machine, not only its target.** Give concrete `Event` constructors, canonical envelope (run identity, sequence, version), `State` fields, initial state, `legal_event(S,e)`, and per-constructor `apply` guard/update. Specify errors/rejection and whether invalid journals yield `Error`; then define `replay` as fold. Current prose says events have envelope fields, while listed minimal payloads omit them; resolve envelope versus payload and state which fields are derived.
2. **Avoid circular WF.** State a syntactic/semantic predicate `WF(S)` independent of `apply` legality. Prove separately: `WF(empty_state)`; for every constructor, `WF(S) ∧ guard_i(S,e) ∧ apply(S,e)=Ok(S') => WF(S')`; replay induction; and rejection from terminal. Do not define legal as “preserves WF” and cite that as preservation.
3. **Quantifiers and domain.** P3 needs explicit `forall J` over canonical, replay-accepted journals and `forall e` over each event constructor, for every fixed valid pinned bundle/context. Distinguish rejected/ill-formed byte strings from accepted journals. Canonical encode/decode should state exact domain, including whether equality is bytes or event-list equality. Current P3 table says “empty journal well formed” although replay signature returns `result`; identify empty journal’s valid run context / pre-start state.
4. **Ledger completeness.** Define budget/fuel equations as constructor-specific state updates, not only invariant summaries. For every successful event prove finite support, nonnegative entries, unique occurrence settlement, conservation, and that projections `budget_ledger`, `fuel_ledger`, `charge_allocations`, `fuel_allocations` are functions of state alone. P8’s intended equations are useful but do not fill missing event updates.
5. **Absorption.** Prove terminal predicate equivalence with the root output wire evaluating from committed outputs plus all graphs/nodes resolved; derive empty frontier and rejection for every constructor. Also prove local completion, call outcome, and graph commitment each absorb their own occurrence, independently of run-terminal absorption.
6. **State determinism / identity context.** State theorem as deterministic `replay_B(J)` for fixed immutable bundle `B`, or make `B` an explicit argument; prove different accepted prefixes can differ but same `B,J` yield equal state. Registry loader stability is P0 contract, not journal bytes. SemWF provenance is deliberately not recovered from bytes; transfer it from authorized append trace and store monotonicity.

## Minimal repair

Add a short transition table plus concrete state record in §4.1. Table columns: constructor; state guard; fields added/removed; derived occurrence/identity values; exact charge/fuel delta; replay-only checks; append-authorization-only facts. Specify `RunStarted` as the sole transition from pre-run state, then the four remaining guards and updates above. Define `legal_event` from those guards, prove each case preserves separately defined `WF`, and only then state replay induction and terminal absorption. Keep `SemWF` as trace-indexed provenance; do not make replay rerun work or effects.

## Strongest objection and unresolved item

**Strongest objection:** P3 acceptance says “deterministic canonical replay and structural WF preservation,” yet transition authority is still hidden in an abstract `apply` and undefined “legal transition.” There is no way to check event completeness, reject counterexample histories, or prove non-circular preservation from this text. This is a substantive S2-05 gap, not merely an F* representation choice.

**Unresolved:** Whether the S2-05 implementer intends an explicit pre-`RunStarted` empty state versus only nonempty run journals. Resolve this when defining initial state, event envelope, and replay context. Current `Journal -> result State` plus “empty journal is well formed” leaves that boundary ambiguous.

**Evidence status:** All repairs and theorem statements above are contract targets. Current evidence ledger says existing `WorkflowV2.Journal.fst` has declarations only and no replay/apply/WF/terminal proof. No source theorem is proved by this audit.
