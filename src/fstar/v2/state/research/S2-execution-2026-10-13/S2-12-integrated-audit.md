# S2-12 integrated packet audit

**Verdict: FAIL.** Packet preserves most normative semantics, but later implementer still must resolve interface and ownership ambiguities before coding. Findings below do not justify weakening any theorem.

## Findings

1. **Signature sketch contradicts its “only dependent telescope” caveat.** [Packet §2, lines 45–94, 177–180](../../../implementation_packet.md#2-contract-surface-and-schematic-signatures) omits normative identity fields from `Codec` and `IndexedCodec`; `GeneratorRef` also omits `input_codec` and `graph_codec`. Normative declarations require these at [spec lines 110–133](../../../implementation_spec.md#2-minimal-typed-api) and [642–655](../../../implementation_spec.md#22-dynamic-graph-description-and-construction-api). The `GraphDesc` sketch additionally hides node key/work-ref/input-wire structure behind an informal list type, while calling out only omitted telescope notation. Since P0/P2 require exact manifest-linked codecs and lossless graph syntax, this is more than universe encoding. **Fix:** include these fields and explicit first-order node shape, or correct the caveat and mark every omitted contract explicitly; keep normative declarations authoritative.

2. **P5 has no coherent module owner/import path; P8 has no named theorem owner.** [Packet architecture, lines 144–150](../../../implementation_packet.md#3-required-source-module-architecture) assigns P5 to `Generation`, whose imports exclude `Journal` and `Durability`, though P5 requires committed event replay and P10 cuts ([spec P5 dependencies, line 2673](../../../implementation_spec.md#6-required-proofs)). `Recovery` owns P16 but not P5. Also no architecture row names P8: `Allocation` mentions ledger projections, while `Journal` owns replay and `Controller` owns P15. **Fix:** place graph-specific exact-result lemma in `Generation`, but assign composite P5 to `Recovery` (or another module importing Journal, GraphCodec/Resolve, Generation, and Durability); explicitly assign P8 and state its import dependencies. Avoid a cycle.

3. **P15 coordinator boundary is underspecified.** Packet names unique claims, one append slot, epochs, and a counterexample for “two coordinators writing without shared fencing” ([lines 150, 299–303, 360–370](../../../implementation_packet.md#3-required-source-module-architecture)), but never states which model P15 proves: one coordinator per run, or multiple coordinators with shared claim/epoch fencing. Normative boundary explicitly chooses one active coordinator and requires extra shared fencing for multiple coordinators ([spec lines 1985–1991](../../../implementation_spec.md#42-abstract-executor-and-service-contracts)); P15 also requires unique live claims ([theorem guide line 174](../../../key_correctness_theorems.md#the-theorem-spine)). Serial journal appends alone do not establish global volatile claim uniqueness. **Fix:** state one coordinator per run as P15 premise and make P13 prove it, or specify shared fencing/claim ownership contract for multi-coordinator deployments.

4. **P8 proof order is executable but ownership missing; P5 order is otherwise sound.** Packet phase D groups P4/P8/P9 and phase E orders P10 before P5 ([lines 225–245](../../../implementation_packet.md#5-proof-order-and-dependency-spine)); that matches spec P4/P5/P8 dependencies. The defect is architecture mapping above, not theorem order. P0–P16 dependency list, including P13/P14/P16, otherwise agrees with [spec theorem table](../../../implementation_spec.md#6-required-proofs) and [key theorem guide](../../../key_correctness_theorems.md#the-theorem-spine).

## Audited areas

- **Events/journal:** five-event payload table matches [spec §4.1](../../../implementation_spec.md#41-canonical-state): occurrence paths/keys, graph or indexed output bytes, plans, resume bytes, evidence/charge/artifacts. Derived request, identity, sequence, parent, and volatile data remain out of event payload. `RunIdentity` plus list index is consistent with run-relative `EventNodeRef`.
- **Codec across restart:** packet correctly requires `ReplayContext` to supply exact codec identity/package, selected from immutable store/run/deployment metadata or fixed deployment context, and P13 restart stability ([packet line 324](../../../implementation_packet.md#7-representation-choices-owner-and-decision-rule)). This closes selector ambiguity without adding a second journal authority; spec requires fixed replay context and journal codec ([spec lines 1491–1497, 1541–1556](../../../implementation_spec.md#41-canonical-state)).
- **Concurrency:** packet correctly keeps workers and distinct adapter keys concurrent, appends serial, commits before dependent visibility, and requires stale reauthorization ([packet §§1, 4, 6](../../../implementation_packet.md#4-journal-representation-and-commit-rules)). It captures epochs/fencing in P13, but needs coordinator premise above.
- **Unbounded graph language/deployment:** packet preserves finite-but-unbounded node count/depth/encoded size, with admission before `RunStarted` and sufficient-capacity premises for P14 ([packet lines 332–342](../../../implementation_packet.md#7-representation-choices-owner-and-decision-rule)); agrees with S2-03 and P14 ([DAG lines 39–53](../../work_dag.md#active-s2-dag), [spec P14 line 2682](../../../implementation_spec.md#6-required-proofs)).
- **Strong counterexamples:** packet includes dependent `Sigma n. vector n` to `vector 3`, runtime validator narrowing, generator sampling, post-commit rerun, child-before-commit, lost reply duplicate effect, stale permit, old epoch, unfenced coordinator, and noncanonical/torn bytes ([packet lines 360–370](../../../implementation_packet.md#8-alternatives-and-decisive-counterexamples)). This aligns with strict universal edge typing ([spec lines 844–897](../../../implementation_spec.md#221-typed-schema-evidence-for-graph-resolution)) and P15/P16 guide.
- **References/contradictions:** cited normative docs and DAG exist. Packet’s “§2.2” pointer at line 177 is ambiguous unless explicitly named as `implementation_spec.md §2.2`; current packet has no §2.2 subsection. More materially, “signatures omit only dependent telescope” is internally false (finding 1). S2-12 acceptance remains `in_progress`, so report is audit evidence, not status completion.

## Strongest objection

P15’s “unique live claims” cannot be implemented from per-controller volatile claims plus a serial journal unless coordinator scope is fixed or shared fencing is specified. Normative spec fixes this boundary; packet leaves it to the implementer. Combined with P5/P8 ownership ambiguity, the packet does not yet fully meet “without inventing semantics.”
