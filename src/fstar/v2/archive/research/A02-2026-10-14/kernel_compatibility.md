# A02 kernel compatibility audit

**Scope:** read-only audit of current `WorkflowV2.Kernel`, its checked build list, importing sources, normative specification, accepted A01 boundary, and active DAG. No verifier run and no source edit. Existing sources are partial evidence; they do not discharge P0–P16 (`implementation_spec.md`, Status).

All seven listed modules are in `Makefile`'s source set: `Kernel`, `GraphCodec`, `Identity`, `Graph`, `GenerationExample`, `ChainProof`, `Journal`. Import edges: `GraphCodec`, `Identity`, `Graph`, `GenerationExample`, and `ChainProof` open Kernel directly; `Journal` opens Kernel and Identity. `Graph` additionally consumes legacy registry and membership definitions from `Identity`. `GenerationExample` and `ChainProof` exercise those legacy structures. Replacing Kernel names or record fields therefore breaks multiple checked modules immediately; deleting or changing `Identity` also breaks `Graph`, both examples/proofs, and `Journal`.

## Gaps against normative API and active plan

- Kernel has required first-order identities, dependent codec/work signatures, first-order graph/wire syntax, callback-only `generator_ref`, and allocation inputs. Current three work cases match intended local / external / generator split.
- Kernel lacks the spec's `SchemaIdentity`, `JournalCodecIdentity`, `ResolverIdentity`, `RootEntryIdentity`, `RegistryManifest` and canonical manifest projection vocabulary. It also lacks schema-expression/denotation syntax, typed artifact-reference syntax, and a run-pinned charge metric. `digest = bytes` is only a representation alias, not a collision-resistance or injective identity law.
- `implementation_spec.md` requires exact manifest/package coherence, canonical syntax resolution, and metric-pinned accounting. A01 boundary assigns first-order manifest/schema entries to `ManifestCore`, schema syntax to Kernel, schema resolution to `GraphResolve`, artifact reference syntax to Kernel, and metric to Kernel. Avoid stuffing executable registries or resolver results into Kernel.
- Active `state/work_dag.md` marks A02 in progress. It sequences Kernel before ManifestCore/GraphCodec, Schema/GraphResolve, Allocation, GeneratorAdmission, Bundle, and later Journal; A02 does not itself complete P0 or C1. A02 acceptance explicitly requires full configured verifier check and tool/result record at implementation completion; this audit did not execute it.

## Safe migration sequence

1. Add the missing stable first-order vocabulary in Kernel, keeping existing public names and layouts initially; pair any `.fsti` with checked `.fst` and add both to build list as A01 requires.
2. Keep `GraphCodec` as the first compatibility client. Preserve current syntax encoding while identity/schema vocabulary expands; any intentional wire change must update codec decoder, roundtrip/canonicality proofs, and journal codec consumers together.
3. Split legacy `Identity.fst`: first-order identity/manifest material to `Kernel`/`ManifestCore`; executable exact package tables and lookup to `Bundle`. Migrate `Graph.fst` consumers only as their A03–A10 successors become checked, rather than importing old admissions/registries into theorem closure.
4. Split legacy `Graph.fst` by A01 ownership: schema resolver, allocation, generator package, builder/splice, interpretation. Retain useful local lemmas only where their dependency closure is clean; do not promote `generator_admission` or admitted builder spine as generic proof.
5. Rebuild `Journal.fst` after typed graph/bundle/allocation interfaces stabilize (A11–A13). It must consume canonical first-order references and pinned metric; do not preserve duplicate `artifact_ref` or budget truth if canonical owners move.
6. Keep `GenerationExample.fst` and `ChainProof.fst` as compatibility checks/examples or retire them explicitly from the theorem build only after replacement. Full build must remain topological and include every active `.fst`/paired `.fsti`; no stale admitted dependency may enter new theorem closure.

## Exact high-risk edits

- Changing `wire` constructors or parameterization breaks `GraphCodec.enc_wire`/`dec_wire*`, `Graph` reference/typing/evaluation lemmas, `GenerationExample` descriptors, and `ChainProof` wire lemmas.
- Changing `graph_node` / `graph_desc` fields breaks `GraphCodec.enc_graph_node`/decoder and syntax roundtrip, `Graph` interpretation/builder, both graph examples, and any journal graph serialization.
- Changing identity record fields/variants or equality shape breaks all matching identity codecs/proofs, `Identity` resolution/comparison, graph labels/work lookup, and sample registry construction.
- Changing codec field names/law shapes or dependent indices breaks `Identity.work_input_*`, `Graph` constant wiring, `GenerationExample` codec records, and downstream graph typing.
- Changing allocation record fields / plan alias breaks `Graph` validity and fuel/charge functions, `GenerationExample` plan constructor/proofs, `ChainProof` allocation proofs, and Journal occurrence allocation.
- Changing `run_budget` fields breaks `Journal.run_started` and all replay uses; add metric changes alongside A15 accounting and corresponding RunStarted/event codec design.
- Replacing/removing `Identity.pinned_registry_bundle` immediately breaks `Graph`'s registry-indexed typing/admission definitions and both example modules; migrate to `Bundle` as one coordinated boundary, not a Kernel-only rename.
