# A00 proof/trust gap audit

**Verdict:** source has useful checked lemmas and one generator-specific proof, but no current source path establishes P0–P16. Builder API crosses explicit F* `assume` boundaries and P1 builder laws use `admit`; graph codec proves syntax only. No verifier was run for this audit.

## Trust boundary and theorem evidence

- **Explicit assumptions:** [`WorkflowV2.Graph.fst`](../../current_implementation/src/WorkflowV2.Graph.fst#L417) declares `graph_builder` and `builder_nodes` with `assume`; [`start_graph` and `add_node`](../../current_implementation/src/WorkflowV2.Graph.fst#L523) are also assumed. These are not merely undocumented implementation choices: downstream statements can rely on arbitrary values satisfying only their declared types. `finish_graph` projects those assumed builder nodes ([Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L570)).
- **Admitted theorem path:** `start_graph_law`, `add_node_appends_exact`, `finish_graph_sound`, and `graph_complete` end in `admit()` ([Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L906)). `graph_complete` concludes only `wire_label_isomorphic`, whose own comment says it omits transport of dependent contexts, resolved signatures, and indexed constants ([Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L123), [Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L146)). This falls short of DAG A08's typed-isomorphism and no-admission acceptance ([work_dag.md](../../schema_era_2026-10-14/state/work_dag.md#L202)).
- **Checked local facts:** `Identity.fst` proves structural identity equality soundness and exact lookup for unique work/codec registries ([Identity.fst](../../current_implementation/src/WorkflowV2.Identity.fst#L6), [Identity.fst](../../current_implementation/src/WorkflowV2.Identity.fst#L117), [Identity.fst](../../current_implementation/src/WorkflowV2.Identity.fst#L254)). `Graph.fst` has constructive typed port/wire constructors and lemmas showing typed wires refer only to existing prior ports ([Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L304), [Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L392), [Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L596)). These are real local proof substrate; they do not discharge graph resolution from durable bytes.
- **Syntax codec:** `GraphCodec.fst` parses complete input (EOF required) and checks accepted bytes equal re-encoding ([GraphCodec.fst](../../current_implementation/src/WorkflowV2.GraphCodec.fst#L108), [GraphCodec.fst](../../current_implementation/src/WorkflowV2.GraphCodec.fst#L124)). Structural induction proves descriptor syntax roundtrip/canonicality ([GraphCodec.fst](../../current_implementation/src/WorkflowV2.GraphCodec.fst#L284)). It does not resolve work references, constants, or graph bytes into a `typed_graph_witness`; do not count it as P2.
- **Journal boundary:** `Journal.fst` defines five event constructors and action vocabulary ([Journal.fst](../../current_implementation/src/WorkflowV2.Journal.fst#L82)); source comment explicitly says replay is future work and vocabulary grants no transition authority ([Journal.fst](../../current_implementation/src/WorkflowV2.Journal.fst#L101)). There is no proof path from event bytes to authorized state.
- **Example:** `ChainProof.fst` constructs a typed witness directly using `TypedNodesSnoc` ([ChainProof.fst](../../current_implementation/src/WorkflowV2.ChainProof.fst#L66), [ChainProof.fst](../../current_implementation/src/WorkflowV2.ChainProof.fst#L105)); it does not call assumed `start_graph`/`add_node`. It proves a particular chain's graph WF and allocation constraints ([ChainProof.fst](../../current_implementation/src/WorkflowV2.ChainProof.fst#L252), [ChainProof.fst](../../current_implementation/src/WorkflowV2.ChainProof.fst#L297)). Its generator admission is universal over that specific generator's input and parent allocation, but generator API lacks run charge metric ([GenerationExample.fst](../../current_implementation/src/WorkflowV2.GenerationExample.fst#L146), [ChainProof.fst](../../current_implementation/src/WorkflowV2.ChainProof.fst#L317)). This is not generic builder completeness, P4 commit authorization, or recovery.

## Specific completeness and trust risks

1. `graph_complete` is not a near-complete P1 proof. Its premise is current `dag_wf`, which can be inhabited by a hand-built `typed_graph_witness`; that witness stores actual F* `Work`/codec membership and wiring evidence. No schema syntax/denotation or durable resolver appears in the source. The theorem is admitted and yields raw `wire_label_isomorphic`, explicitly weaker than typed context transport ([Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L763), [Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L931), [Graph.fst](../../current_implementation/src/WorkflowV2.Graph.fst#L146)). It cannot establish spec completeness for `SchemaSupported`.
2. `typed_graph_witness` gives a meaningful indexed proof for a graph already accompanied by actual F* typed evidence. It does not establish that untrusted decoded `GraphDesc` bytes can obtain that witness. Conflating witness existence with resolution would make P2 appear solved by definition.
3. Registry uniqueness means at most one matching **full `DurableWorkRef`** in a table. It does not establish that `RegistryIdentity` names these contents, that a code/operation identity uniquely selects a coherent package across every table, or that a restart selects same package ([Identity.fst](../../current_implementation/src/WorkflowV2.Identity.fst#L92), [Identity.fst](../../current_implementation/src/WorkflowV2.Identity.fst#L284)).
4. `GraphCodec` canonicality is a bytes/syntax claim. It accepts only complete syntax bytes, but does not check graph WF or resolve a constant codec/work reference. A syntax roundtrip cannot imply P1/P2 ([GraphCodec.fst](../../current_implementation/src/WorkflowV2.GraphCodec.fst#L124), [GraphCodec.fst](../../current_implementation/src/WorkflowV2.GraphCodec.fst#L124)).
5. The generator contract record is not an unchecked assumption by itself; callers must construct its proof fields. Yet source only constructs a chain-specific inhabitant. Also its callback takes `(x, allocation)` while spec/A16 require run metric as input; no metric coherence can be inferred ([Kernel.fst](../../current_implementation/src/WorkflowV2.Kernel.fst#L167), [work_dag.md](../../schema_era_2026-10-14/state/work_dag.md#L200), [implementation_spec.md](../../schema_era_2026-10-14/implementation_spec.md#L642)).
6. The no-`assume`/no-`admit` project acceptance will require replacing the builder abstraction, not merely proving more lemmas around it. Even if other current lemmas verify, downstream theorems that transitively use builder terms inherit this trusted boundary. The only source `assume`/`admit` occurrences found by direct search are in `Graph.fst`; exact lines above.

## Hardest blocker and next proof experiment

**Hardest blocker:** P1/P2 lack sound and complete bridge from durable syntax to dependent graph witness. Current general builder itself is axiomatized/admitted, while current `dag_wf` relies on a witness already carrying F* types. This is a semantic trust gap; proving more chain lemmas or syntax codec lemmas will not close it.

**Concrete next experiment:** implement only A05–A07's smallest schema fragment in a fresh proof module: `Nat`, `Vec(n)`, exact manifest-pinned denotations, legal environments, and an equality derivation checker with no solver-success constructor. Define one direct-output graph resolver. Prove two results: (1) unrestricted `Work nat (fun n -> Vec n)` cannot feed `Work (Vec 3) ...` because edge equality fails for a legal `n`; (2) the same edge resolves when graph static constraints entail `n = 3` for every legal environment. Ensure the resolver returns a typed witness from syntax alone and module has no `assume`/`admit`. This sharply tests the universal-edge/completeness boundary before replacing builder or layering P3–P16 on it. It corresponds to DAG A05–A07 and the decisive counterexample ([work_dag.md](../../schema_era_2026-10-14/state/work_dag.md#L196), [work_dag.md](../../schema_era_2026-10-14/state/work_dag.md#L198), [implementation_spec.md](../../schema_era_2026-10-14/implementation_spec.md#L854), [key_correctness_theorems.md](../../schema_era_2026-10-14/key_correctness_theorems.md#L51)).
