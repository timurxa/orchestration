## Decisions and evidence from legacy V2-03 phase

The decision record above is authoritative for the current API. Earlier
recommendations are historical where they differ.

The local equality-certificate design is exploratory, not yet selected. The
work-pair compatibility table remains insufficient for graph-specific
dependent edges; do not treat it as the current resolver decision.

The chain generator is now a verified concrete admission example, not a
generic resolver result. It establishes the arbitrary-input shape and plan
contracts for one generator. V2-03 remains open because decoded graph syntax
still cannot be turned into exact typed `Wiring` for every accepted descriptor.
Earlier scratch chain-proof claims were audited and invalidated: the source
module names did not match the temporary filenames, so F* skipped the proof
files. The matching repository module is now verified in the full build.

The resolver feasibility note supersedes early claims that a handler or token
manifest alone automatically closes the arbitrary `Type0` gap. A handler is
constructive for the graph language it accepts; complete support for every
current `graph_wf` witness still requires proof/schema reification or a changed
well-formedness boundary. The V2-03 representation decision is open; dependent
nodes remain unstarted.

- Retain a first-order finite DAG with an explicit topological permutation and
  a syntax-directed dependent wire-typing witness. Remove the unnecessary
  requirement that topological order equal numeric key order: keys identify
  occurrences, while the order witnesses acyclicity.
- Retain source nodes through root and codec-backed constant wires. The builder
  completeness target covers all finite typed DAGs described by the spec's
  wire language, including independent/dead nodes, fan-out, repeated work at
  distinct occurrence keys, and arbitrary topological key order.
- Keep the staged declaration milestone distinct from proof discharge. V2-01
  and V2-02 are ready for the requested human review; their theorem bodies,
  registry linkage, port laws, and typed isomorphism remain open. The current
  `verify` result means F* accepted the declarations and non-admitted VCs; it
  does not validate the truth of `assume`/`admit` contracts.
- The pre-implementation identity audit and adversarial report remain valid as
  historical gap inventories, not as descriptions of the current source. See
  the implementation addendum and `V2-02-implementation-review.md` for the
  post-edit status.
- `pinned_registry_bundle.bundle_identity` is not currently proved to name the
  actual work/codec registry contents. This is a P0 blocker, distinct from the
  host reload/build-refinement premise. Journal events are uniquely identified
  by `(run, sequence)`; no separate event identifier is retained.
- At this historical snapshot V2-03 was active. The investigation brief fixed acceptance: concrete
  round-trip/canonical graph encoding, resolution of decoded graph references
  to exact typed registry entries, and generation at exact dependent indices.
  Worker proposals are read-only until integrated and verified by root.

multiple distinct calls may remain in flight; the journaler serializes one
append at a time; local/generator executor can execute independent ready
occurrences concurrently. Adapter retries require stable-key
deduplication/status lookup or operation-specific idempotence/reconciliation.

all-interleaving safety; P13 concrete refinement; P16 every-cut recovered
semantic graph correctness. The theorem dependency table is acyclic: P4/P6/P7
do not depend on aggregate ledger theorem P8; P8 composes their transition
laws with replay.
