# Final proof review

**Scope.** Independent review of `design_comparison_and_decision.md` and `refined_proof_targets.md` against controlling spec and current F* / OCaml source. Findings only; no edits to integrated design, builds, or tests. Labels: **Source fact**, **Formal gap**, **Conditional claim**.

## Assessment

Strong improvement: documents distinguish model theorem, adapter assumption, and host refinement; reject exactly-once by local IDs; identify no current extracted-runtime proof. Remaining blockers are statement precision, completion/publication visibility, and protocol accounting. None of P1–P7 is established by current prototype.

## Main proof gaps

### Completed-node no-rerun (P2)

**Formal gap:** P2’s quantifiers do not constrain `trace` to a trace generated by `Resume` under evaluator semantics. As written, arbitrary `trace` may contain a body call while premises hold. Add `ResumeTrace(D,V,B,A,Q,W,x,t)` plus initial-state relation, and quantify completion record identity against that exact `run,k,inputDigest,planDigest`. “Valid committed states” should mean a completion accepted by checked replay/validation, not mere record presence.

**Missing implication:** `CompletionRecord(D,A,k,a,w) /\ Pinned(...)` does not itself prove that the queried `k` is in this resumed plan, that result belongs to this input, or that occurrence identity is collision-free. Completion key needs run ID, structural occurrence path, input/request digest, output schema/version, node kind, and pinned code/build/validator identity. State an injectivity/uniqueness invariant. A previous completion for same path but different input must fail closed, never be consumed.

**Good statement direction:** after a *validated completion for exact occurrence/input/plan* exists at resume start, prove evaluator lookup precedes local body and effect dispatch; successful checked decode returns same typed result/evidence. Then prove extracted loop simulates this. The integrated doc correctly says this lookup is a lemma, not premise. But no memo table exists today: `pure` invokes callback every evaluation; `resume_evaluate` decodes root and reevaluates plan (`WorkflowCore.fst:464-481,855-864`). External `Succeeded` short path is not generic local memoization and decodes output without semantic validator (`969-1030`).

**Scope caveat:** if bytes/checker are unavailable/corrupt after a completion, strict “never invoke body” may mean return explicit unavailable/corrupt, not recompute. State this. Otherwise recovery can preserve usability only by weakening no-rerun.

### Every-cut recovery (P3)

**Conditional claim:** P3’s `StorageRefines`, `Pinned`, `AdapterSafety`, and `evidence checks` carry most of theorem. Define each as a separate predicate and prove it does not say “recovery returns same state,” “no partial completion is visible,” or “the runner follows protocol.” Refined targets make a useful start: enumerate subcuts and insist completion is not defined as recoverable. Still need concrete transition relation for every host primitive and each allowed crash result.

**Cut obligations to retain:** snapshot temp write/flush/fsync/rename/directory sync; SQLite transaction begin/commit; crash before/after dispatch marker; call entry; backend effect before reply; reply persistence; validation; artifact partial write; bytes durable; manifest stage; completion commit; in-memory projection; downstream consume. For each cut, map restored bytes to old/new/explicit uncertain state. Current Runner snapshot is JSON file atomic-rename style, not SQLite; directory `fsync` errors `EINVAL`/`EBADF` are ignored, so durability assumptions must match actual OS/filesystem and platform. Snapshot lock serializes writes, not multiple run loops or external calls. **Source fact:** `Runner.ml:94-140,193-290`; `WorkflowStore` encodes/replays wire state only (`WorkflowStore.fst:327-339`).

**Observation hole:** “observations committed before c are preserved” needs define commitment/visibility. If backend effect occurred before c but local journal lacks reply, effect is not a committed local observation. Require backend history in observation relation; resume may report Unknown while effect exists. If a consumer externally observed artifact or result before workflow completion, include that publication as effect and ensure it is fenced/transactional.

**Equivalence not automatic:** P3 safety is plausible under narrow storage and adapter contracts; uninterrupted/restarted equality needs backend-state relation and scheduler relation. The docs correctly say so. Ensure `BackendBisim` relates actual states after matched pre-cut effects, not a hand-chosen shared reply stream. Tests only sample cuts; they cannot prove the universal cut theorem.

### Artifact staging/publication (P6)

**Visibility gap:** “persist bytes, verify digest, publish references, then commit workflow completion” creates a window where a published manifest/ref may be externally visible before completion. Either keep manifest private/staged until completion transaction; or specify that refs are not consumer-visible until completion; or prove publication is harmless/retractable and recovery protocol handles it. `ManifestValidated` and “publish references” need distinct states: validation is not publication.

**Cross-store atomicity:** bytes, manifest, journal, and completion may live in distinct stores. Content-addressed immutable blobs permit safe orphan bytes, but do not alone prevent a committed completion pointing to absent bytes after power loss. Need store contract for durable put/read-after-commit, hash verification, manifest atomicity, journal commit, and ordering. If failures can corrupt/loss bytes after acknowledged durability, restore must mark unavailable and not consume; no proof can promise artifacts always remain available without stronger storage assumption.

**Provenance gap:** a digest binds bytes under collision resistance and correct hash/store implementation; does not prove bytes came from declared tool/path or satisfy semantic claim. F* path validation does not prove OS path confinement, symlink/race safety, process output, required-file existence, or exact read bytes. Keep these as adapter/host refinement assumptions, and require checker soundness for semantic results. Current reducer only checks shallow artifact shapes/provenance-parent existence, rejects `MaterializedFile`/`LiveCapability`, and has no digest-backed blob store or atomic link from `ArtifactSaved` to success (`WorkflowCore.fst:654-668,762-768`; source map).

### Adapter progress and `Unknown` (P4)

**Good direction:** “dispatch-quiescent, not terminally absorbing” avoids both blind retry and permanently frozen evidence refinement. Current reducer allows several `Unknown -> terminal` status changes; it does not encode authenticated correlated evidence, so current transition permissiveness is not a proof of adapter safety (`WorkflowCore.fst:719-761`).

**Progress theorem must pin actor lifecycle:** `AttemptQuiesces` needs durable dispatch marker, unresolved attempt, finite-crash stable interval, weak fairness, finite store commit, advancing deadline, terminating validation, and bounded killable adapter. Add stale-worker fencing: a worker killed/timed out may later return; its late reply must be correlated to same attempt and cannot overwrite terminal/Unknown projection or trigger a fresh attempt. If watchdog cannot kill/isolate call, no bounded-call premise. Also distinguish “durable Unknown” from “store unavailable”: when store cannot append, no theorem can promise durable quiescence. Current dummy queue and adapter calls do not show real worker interruption or late worker behavior (`Runner.ml:143-171,193-290`).

**No hidden success premise:** terminal-or-Unknown is only useful if attempt starts unresolved and `Unknown` transition is enabled/fairly scheduled after timeout. Do not let “may persist Unknown” be an unconstrained transition that proves liveness. Specify timeout event, durable deadline/retry counter, enabledness, and proof that finite steps lead to commit under store progress.

**Correlation/authenticity:** `Applied`/`NotApplied` evidence must bind run, occurrence, attempt, operation/config digest, request digest, and backend result. A signed response only proves signer said it unless signer is trusted to reflect actual backend state. Adapter contract must state truth/idempotency semantics.

### Attempt-aware budget (P5)

**Potential accounting hole:** invariant sums one charge/reservation per attempt, yet same-key retries and reconciliation may incur repeated provider/adapter costs. Either reserve a bound covering *all* cost of that attempt, including retries/polls/reconciliation; or add per-call ledger entries, budgets, and caps. State which budget means: provider spend, admitted estimate, or internal accounting.

**NotApplied policy:** “releases it” and “records zero operation charge” are valid only if contract establishes no charge for that attempt. A backend may charge request/lookup fees despite not applying requested effect. Model actual known charge separately from effect-applied status; release only unused reservation, settle authenticated charge. Same for failed/cancelled operations. Conservative full-reservation settlement is ledger accounting, not actual-spend evidence.

**Necessary uniqueness details:** `Latest(k)` and at-most-once settlement need reducer invariants over the *journal*, not just current projection. Prove each attempt has exactly one intent, reservation amount is immutable, settlement event has unique id, duplicate/late/conflicting settlement is rejected, same-key retry cannot double-count, and concurrent admissions serialize against one committed state. Overcharge/quarantine must preserve invariant without silently dropping actual cost. Current F* arithmetic lemmas prove `spent + reserved <= limit` for accepted transitions, not authenticated external charge or concurrent host linearization (`WorkflowCore.fst:262-305,681-768`). Current status events lack correlation/authentication evidence.

## Other consistency concerns

- P1 is a pure value/evidence composition theorem, not durable composition. Keep it separate from indexed codec soundness, runtime plan identity, completion persistence, and extraction. The design does this in broad outline.
- `OpOutcome` as a work result includes `Unknown`/failure data, while pending/dispatch/reconcile are runtime states. Specify whether `Unknown` becomes a downstream value only after durable projection and how retry/reconciliation is represented without changing typed result unsafely.
- `DispatchMayHaveOccurred` marker before adapter call is conservative, but prove no call path bypasses marker. If crash happens after `IntentCommitted` before marker, recovery may safely begin; if marker commit itself is ambiguous, treat as may-dispatch.
- Inline/library equality cannot follow from equal labels/config. Need same pinned implementation identity or a proved behavioral relation. Integrated doc notes this.
- Ordinary F* and extracted effect boundary remains open. `Tot` callbacks can be recomputed, but F* totality does not prove extracted callback has no hidden OCaml effects or terminates under host resources. Keep purity/extraction refinement as explicit premise.

## Minimal exact edits to theorem statements (for later author)

1. Add `ResumeTrace` / `RecoveryTrace` premises generated by specified transition relation; quantify same exact run, plan, input digest, occurrence, and accepted completion.
2. Make completion uniqueness + immutable pin relation explicit; invalid/missing completion gives unavailable/corrupt, never silent re-execution.
3. Define storage refinement per primitive and allow only old/new/uncertain states after each cut. Do not hide recovery guarantee inside predicate.
4. Split artifact staging, manifest validation, publication visibility, and completion; enforce completion as consumer visibility gate.
5. Extend budget ledger to all cost-bearing calls or reserve a proven whole-attempt maximum; separate effect application from charge.
6. Add late-worker fencing and durable timeout action to progress assumptions/theorem.
7. Keep unconditional result: prefix safety plus Unknown absent backend cooperation. State stronger equality only under backend and scheduler bisimulation.
