# Final proof review: resolution delta

**Scope.** Revised `design_comparison_and_decision.md` §§8–9 vs. prior `final_proof_review.md`. No source edits/builds/tests.

## Resolved in design statement

- **P2 trace identity:** now quantifies traces generated by resume transition relation; binds run, plan digest, input digest, occurrence, node/schema/code/checker/adapter identities. Invalid/unavailable completion fails closed. Prior arbitrary-trace and wrong-input objections resolved at specification level.
- **Artifact visibility:** manifest is private/staged; consumer resolution gated by matching completion. Cross-store crash/index-update proof remains required, but visibility ambiguity resolved at design level.
- **Late worker / timeout:** durable timeout action is explicitly enabled; worker fenced by attempt/request; late reply cannot rewrite newer terminal state. Store outage caveat prevents vacuous durable-Unknown claim.
- **Unknown:** explicitly dispatch-quiescent, evidence-refinable, history-preserving. Timeout/process death cannot imply non-application; fresh attempt requires evidence. Semantics now clear.
- **Observation identity:** committed observations and unjournaled backend effects distinguished; latter remain possible/Unknown. This fixes earlier observation-scope ambiguity.
- **Storage cuts:** actual JSON snapshot and possible future SQLite cuts named separately; per-primitive old/new/uncertain mapping required. This fixes conflation of backends, but does not itself discharge mapping/refinement.

## Remaining blockers / objections

1. **No concrete host-cut map yet.** P3 says to map each cut to exact old/new/uncertain state under storage contract; it does not enumerate outcomes for current `Runner.ml` temp create/write/flush/fsync/rename/dir-fsync, or prove them. Directory `fsync` may ignore `EINVAL`/`EBADF`; claim must match supported host/filesystem. This remains a theorem/refinement obligation, not a resolved fact.
2. **Charge ledger still undecided.** P5 offers whole-attempt cap *or* per-call ledger, then invariant still says `spent = sum(charge(k,a) for settled attempts)`. If per-call model chosen, equation and identities must sum calls, and include reconciliation/poll/retry costs. If whole-attempt model chosen, prove cap covers all those costs. NotApplied correctly no longer implies zero charge; define settlement events for known charges and unused reservation. Choice not resolved yet.
3. **Progress mechanism remains an assumption.** “Every unresolved attempt has an enabled durable timeout action” and deadline advancement are premises. Next spec/runtime must define stored deadline/counter, event enabling, restart semantics, scheduler fairness, and late worker fencing implementation. Current dummy runner has no killable async worker or durable timeout protocol.
4. **Evidence relation still needs formal content.** Unknown refinement is specified, but authenticated `Applied`/`NotApplied`, correlation, and truthfulness remain adapter axioms. Current reducer accepts `Unknown -> Succeeded/Failed/Cancelled` without correlated proof; `OperationNotAppliedConfirmed` checks adapter ID/nonempty evidence ID only. Do not present this as current safety proof.
5. **Completion digest assumptions:** P2 identity now exact structurally; if digest fields stand for hashes, state collision resistance/canonical encoding assumption or use injective canonical IDs. Prove uniqueness against journal replay and conflicting duplicate completions.

**Conclusion:** prior conceptual gaps mostly closed in §§8–9. No proof/runtime blocker disappears: host refinement, adapter evidence truth, timeout implementation, and selected charge model remain unresolved obligations. Strongest unconditional design claim remains prefix safety with explicit `Unknown`; current implementation establishes none of the new end-to-end claims.

## Post-review resolution recorded in the final decision

The integrated design was revised again after this audit:

- Added a target old/new/uncertain outcome map for current JSON snapshot phases, including the explicit limitation that ignored directory-sync errors cannot count as durable commits. This specifies the refinement target; it does not prove current `Runner.ml` satisfies it.
- Chose a **per-call** ledger for dispatch, redelivery, poll, and reconciliation, with stable call IDs and individual reservations/settlements. Provider-reported spend remains a separate claim. Overcharge is preserved and quarantines new admissions.
- Added explicit `ReportsApplied`/`ReportsNotApplied` truth assumptions, completion-key hash assumptions, and analyzer report provenance. These do not remove the stated provider/host trust boundary.

The remaining concerns listed above are therefore implementation/refinement obligations rather than open design alternatives. The research phase still does not establish them.
